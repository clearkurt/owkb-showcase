# 内容治理

> 本文件描述 OWKB 的导入、审核与回滚原则，不包含真实项目资料或凭据。

## 1. 导入流程

```text
来源确认
  → 格式转换/规范化
  → 质量检查
  → 安全检查
  → 元数据补全
  → 内容写入
  → 索引重建
  → Git 提交
  → 抽样检索验证
```

每一步都应该可重跑，失败时不应留下半成品。

## 2. 来源与授权

导入前需要确认：

- 文档/源码是否有权进入内部知识库；
- 是否允许被 agent 读取；
- 是否需要脱敏；
- 原始文件的归档位置和保留策略。

公开仓库只放脱敏设计文档，不放原始手册、客户工程或凭据。

## 3. 格式检查

### Markdown

- frontmatter 可解析；
- id 唯一；
- 标题层级合理；
- 页锚点和图片引用可解析；
- 没有乱码、替换字符或未闭合表格。

### 手册

- `full.md` 和 `snapshots/` 同目录；
- 页锚点覆盖正文；
- 图片路径相对且存在；
- 表格/框图没有明显丢失。

### 源码镜像

- 与来源工程逐文件一致（或明确标注转码）；
- 不包含构建产物、密钥、证书和临时文件；
- 不修改原始工程。

## 4. 安全检查

至少扫描：

- token、密码、API key、私钥；
- `.env`、证书、凭据文件；
- 个人隐私数据；
- 上传包中的隐藏文件/路径穿越；
- 压缩包大小、文件数、压缩比异常；
- 公开前检查 Git 历史中是否曾提交过敏感文件。

## 5. 索引与健康

- 内容变化后重建索引；
- 检查文档数、块数、孤儿数；
- 检查重复内容；
- 检查索引构建耗时和失败日志；
- 抽样执行检索回归。

## 6. 回滚

内容使用 Git 管理，索引可重建，因此回滚应优先：

1. 回退内容提交；
2. 重建索引；
3. 验证关键检索；
4. 记录原因和影响范围。

不要直接编辑索引数据库来“修复”内容问题。

## 7. 公开仓库特别规则

公开前必须确认：

- 不含厂商手册原文、客户项目资料、公司源码；
- 不含 token、证书、服务器地址、内网信息；
- 历史提交不含敏感文件；
- README 明确说明仓库范围和限制。

如果历史中曾提交过敏感文件，必须重写历史或新建干净的展示仓库，不能只删除当前文件。
