# Agent 集成

> 本文件描述 OWKB 的只读 agent 接口设计，不包含生产端点或凭据。

## 1. 接口形态

OWKB 可以同时提供：

- 普通 HTTP 只读 API；
- MCP Streamable HTTP 工具接口。

对 agent 来说，MCP 更适合把检索能力作为工具暴露；HTTP API 更适合脚本、
监控和内部集成。

## 2. 建议的工具集合

| 工具 | 作用 |
|---|---|
| `search` | 全文检索，返回标题、路径、片段、页/行范围 |
| `read` | 按文档 id 或路径读取正文与上下文 |
| `tree` | 浏览集合和目录结构 |
| `list` | 按标签/类型/集合筛选文档 |
| `health` | 服务与索引健康状态 |

工具应该返回结构化结果，而不是只返回一段不可引用的字符串。

## 3. 检索结果应包含什么

一个适合 agent 使用的结果至少应包含：

```json
{
  "id": "example-doc",
  "title": "示例文档",
  "path": "content/示例/example.md",
  "collection": "示例",
  "page": "12",
  "line_start": 120,
  "line_end": 150,
  "snippet": "……",
  "score": 12.3
}
```

这样 agent 才能：

- 引用具体文档位置；
- 判断是否需要继续读取上下文；
- 在回答中区分“手册事实”和“项目经验”。

## 4. 只读边界

MCP/HTTP 数据接口不应提供：

- 任意文件写入；
- 任意命令执行；
- 数据库管理；
- token/证书读取；
- 生产配置修改。

知识导入、索引重建、移动/删除应由管理员通过 CLI 或受控后台完成。

## 5. 认证与权限

建议采用：

- 按调用者的只读 token；
- TLS/mTLS 或等效的传输认证；
- 设备/客户端绑定（可选）；
- 按 collection 的权限分组（可选）；
- 全量访问审计。

永远不要把管理 token 分发给普通查询客户端。

## 6. Agent 使用建议

1. 先检索，再读取上下文；
2. 优先引用文档路径和页/行号；
3. 对“没有检索到”的结果明确说明，不要猜测；
4. 技术结论区分源码事实、手册事实、推断和待确认；
5. 不把检索到的内部资料复制到公开渠道。

## 7. 失败处理

- 索引未构建：返回明确状态，不返回空结果冒充“没有资料”；
- 文档不存在：区分“路径不存在”和“没有权限”；
- 服务不可用：由客户端重试并记录错误；
- 检索超时：限制返回大小和查询范围。
